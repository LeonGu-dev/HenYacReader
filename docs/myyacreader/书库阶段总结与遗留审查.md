## 优先处理的遗留

### 1. 信息导出／导入没有覆盖新增字段

位置：`YACReaderLibrary/db/data_base_management.cpp` 的静态 `fields`、`DataBaseManagement::exportComicsInfo()` 和 `importComicsInfo()`。书库菜单仍直接调用这些函数。

导出字段和导入 SQL 手工列举旧字段，缺少 `DescriptiveComicMetadata::personalColumns()` 定义的 11 个新增字段：标题翻译、社团、作品、合同本、修正、翻译状态、译者、最爱、类型、即卖会、系列。title／writer／characters／tags／rating 等部分信息仍会保留，但**不能用此功能完整迁移或备份新版元数据**。

建议共用字段定义、明确旧文件兼容策略，增加全字段导出→新库导入的往返测试。XML/CBL 交换也仍沿用旧格式，应另行界定支持范围。这不表示本地 `library.ydb` 没有保存新字段；完整书库数据与此元数据导出是不同概念。

### 2. 列表即时评分忽略写库结果

位置：`YACReaderLibrary/db/comic_model.cpp::updateRating()`、`resetComicRating()`。

这两条路径忽略 `DBHelper::update()` 的返回值，随后更新内存评分。写入失败时可能看似已保存，重新打开后恢复旧值。此结论来自代码审查，本轮未制造数据库故障复现。

编辑窗口的新版评分保存路径已有不同处理，不是所有评分保存都失效。建议即时评分改用现有专用更新函数，检查结果，成功后更新界面，失败保留原值并提示。

### 3. “删除元数据”仍使用旧清除定义

位置：`common/comic_db.cpp::ComicInfo::deleteMetadata()`，由 `ComicModel::deleteMetadata()` 调用。

它清除标题、作者、角色等旧字段，但没有清除新增的 11 个字段；旧 tags 原本也没有清除。因此可能出现标题作者为空，而作品、系列、即卖会等仍在的混合状态。该调用也没有完整检查事务和更新返回值。

应先明确哪些整理信息要清除，是否保留最爱、评分、进度，再统一实现并测试回滚，不能直接清空全部列。

## 已知边界

- 文件夹范围只含直属漫画，不递归；保存目录 ID，改名仍有效，删目录后为空，不退回全库。
- 智能列表保存元数据条件，不保存主搜索文字，也不基于当前阅读列表成员；普通列表保存当时右侧结果。
- 文件名解析是启发式规则；无无修正标记不推断有码，仍需人工复核。系列暂无卷序号或文件名语法。
- 多文件可以因相同快速指纹共享信息和进度；标题不是唯一键。重命名只改当前文件。
- 元数据在 `.yacreaderlibrary/library.ydb`；标签颜色在应用 INI 配置，复制书库不会自然携带所有外观设置。
- 小屏幕、长标签或展开候选时仍需要滚动；默认高度无法保证任意内容都无滚动完整展示。
- 全屏退出短暂恢复普通窗口再最大化，是已讨论并暂缓的 Qt 行为，Esc 保留。
- 当前主要验证 Windows / Qt 6.9.3 / MSVC 2022；未完成其他平台发行、安装包／签名和真实超大库性能基准。
